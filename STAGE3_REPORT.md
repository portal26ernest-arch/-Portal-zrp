# PORTAL NEXT b003 — отчёт Этапа 3

Дата проверки: 25.09.2026. Ветка: `portal-next-b003`. Работа продолжена с существующего рабочего дерева после Этапа 2. Откатов, перехода на main, push, merge и изменений рабочей базы телефона не было. После проверок Этап 3 зафиксирован локальным контрольным коммитом. Миграция рабочей БД **не запускалась**. Финальная b003 и APK не выпускались.

## Реализовано полностью

- Партии с автоматически присваиваемым глобально уникальным номером PORTAL, компанией, клиентом, товаром, количеством, датами, внешним документом, статусом и связью с выработкой, материалами и отгрузкой.
- Задания с исполнителями, остатком и сроком. Работа по заданию и «Другая работа» без задания; последующая привязка свободной записи к партии без изменения исторических сумм.
- Раздельные версионные ставки сотруднику и цены клиенту с датой начала действия. Выработка хранит денежный снимок тарифа; последующие изменения не пересчитывают зарплату, начисление клиенту или выставленный счёт.
- Индивидуальные разрешения поверх рекомендуемых наборов ролей, включая «Просматривать историю входов сотрудников»; защита Platform Owner и границ компании. Новые API проверяют права на сервере.
- План/факт/отклонение партии, фактические расходы материалов, финансовые агрегаты клиента и партии, счета, частичные оплаты и дебиторская задолженность.
- Журнал успешных и отклонённых входов, тип Android/PC-Web, точное время, последняя активность и подтверждённый выход. PIN, пароль и токен в новом журнале не сохраняются. Online определяется по активной сессии и heartbeat; несколько устройств учитываются отдельно, logout переводит в Offline при отсутствии других сессий. Интервалы heartbeat/timeout задаются настройками компании.
- Таймер задания: начать, пауза, продолжить, завершить; интервалы пауз, календарное и чистое время, объём и ед./час. Завершение создаёт обычную сдельную выработку; время не меняет тариф зарплаты.
- Экран «О системе PORTAL» с утверждённым текстом и единым указанием разработчика и правообладателя. Версия, build, сервер и проверка соединения сохранены.

## Архитектурная подготовка

- `PORTAL Сегодня`, блок «Требует внимания», разделы меню, «Финансовый радар», `PORTAL Аналитика` и правила проверки невыставленных работ в понедельник и неоплат в среду. Расчёты основаны на первичных операциях. Внешний scheduler и AI API не подключены.
- Доступ к данным вынесен в company-scoped репозиторий; подготовлены PostgreSQL DDL, RLS и SQL-адаптер. Работающий сервер пока использует SQLite и унаследованные проекции Этапов 1–2. PostgreSQL cutover не выполнен.
- Будущий чат не реализован. Для него предусмотрен отдельный контур company_id: системные файлы «Стикеров PORTAL» должны храниться однократно и адресоваться по ID; история и пользовательские вложения — максимум 14 дней, с исключением закреплённых сообщений. Внешний мессенджер не входит в целевую архитектуру APK/Desktop PORTAL.
- «Смена склада» не реализована; остаётся в roadmap. Документы и часть аналитических рекомендаций остаются будущими модулями.

- Проверены тестами права, межфирменная изоляция, уникальность номеров партии, версии тарифов, сохранение денежных снимков, таймер и неизменность сдельной зарплаты. Поиск по коду и проверка ledger в тестах не выявили сохранения PIN/паролей/токенов в новом журнале или production audit.

## Ограничения среды

- Локального Android SDK нет: Debug APK не собран. GitHub Actions для сборки APK сохранён; финальный b003 выпускать после проверки на устройстве.
- PostgreSQL и реальный VPS отсутствуют; DDL и адаптер подготовлены, но интеграционный тест на PostgreSQL не выполнялся.
- Серверные тесты выполнялись на временных БД через in-memory HTTP harness. Реальный HTTP в Windows не использовался для итоговой оценки: ранее наблюдался WinError 10054. Это ограничение среды, пока unit/browser проверки проходят.
- Прогноз завершения заданий и контроль счетов — правила при открытии экрана, без фонового scheduler. Последняя активность обновляется при запросах с ограничением частоты записи и при heartbeat; внезапное закрытие клиента определяется таймаутом, достоверный `ended_at` ставится при logout.

## Что проверить после PostgreSQL

1. Применить миграции на отдельной тестовой БД и проверить повторное применение, транзакционность, RLS/`FORCE ROW LEVEL SECURITY`, отсутствие доступа между company_id, индексы и права отдельного DB-пользователя PORTAL.
2. Импортировать снимки с исходными ID, датами и денежными значениями; сверить выработку, зарплату, тарифы, материалы, счета, оплаты, партии и аудит до cutover. Отдельно проверить sequence номеров партии и никогда не переиспользовать выданные номера.
3. Прогнать серверный/API-набор на PostgreSQL и проверить параллельные создания партий, идемпотентные запросы, несколько сессий, heartbeat, таймер и закрытие расчётного периода.
4. Разместить PORTAL отдельным каталогом/сервисом, БД и пользователем БД, окружением, логами и резервными копиями на общем VPS. Проверить резервное восстановление и наблюдаемость.
