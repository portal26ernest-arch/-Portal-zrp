## Scope limits and follow-up

- Static source search found no production server DDL declaring financial columns `REAL`; PostgreSQL compatibility DDL uses `NUMERIC`. SQLite's deployed legacy schema is imported and variable, so its actual column affinities and row values are **unknown** without a separately authorized disposable snapshot.
- `REAL` occurrences in the inspected server code are confined to synthetic SQLite tests. No query of production data was performed.
- No conversion, backfill, rounding, or destructive schema change is approved by this inventory. Financial history remains in place.
- Read-only synthetic linked-work reconciliation compares legacy major-unit values with canonical integer-minor-unit facts using Decimal half-up rounding, reports matched/unlinked counts, and fails closed on drift or duplicate links. Direct cost reconciles against same-company `norm` usage; `additional_actual` remains append-only and does not rewrite the legacy snapshot. An earlier whole-company PostgreSQL run exposed duplicate `legacy_id` values created by historical payroll test clones; the clones now leave that compatibility key empty. The strict unfiltered whole-company disposable PostgreSQL test passed at `b4e0088` in Web run `36725887913` (31 tests, 2 skipped, cleanup `db=0 roles=0 temp=0`). This proves the synthetic test history, not any imported/deployed SQLite snapshot. A real imported snapshot rehearsal remains a separate authorized disposable-snapshot gate; never use production as a test database.
