# PORTAL NEXT b003 — отчёт Этапа 2

Дата проверки: 25.09.2026. Ветка: `portal-next-b003`.

Реализация Этапа 2 завершена в рабочем дереве; это **не финальный релиз**.
Проверки UI и серверных обработчиков успешны. Сборка APK и реальные HTTP-тесты
не подтверждены по причинам, описанным ниже.

## Состояние при возобновлении

Первоначальное задание восстановлено из предыдущей задачи. В ней работа
остановилась по лимиту, а не после завершённой проверки.
Уже существовали изменения Этапа 1, модульный интерфейс, bridge и метаданные
Этапа 2. Они сохранены; повторной реализации и откатов не было.

HEAD и main остались на `d25ef2146f9a98e61d31582a562805c68fe3f331`.
Коммиты, staging, push, слияния и изменения рабочей базы телефона не выполнялись.
Старые APK/SHA256 b001 остались нетронутыми untracked-файлами.

## Что исправлено и завершено при возобновлении

- Исправлена отсутствовавшая закрывающая скобка объекта `storage` в `app.js`.
  Она полностью останавливала выполнение UI (`Unexpected token ';'`, затем
  `screens is not defined`).
- Ответ 401 во время POST принудительно очищает сессию и возвращает вход:
  обычная защита от выхода при незавершённой записи больше не блокирует это.
- Закрытие формы кнопкой, Escape, Android Back и нажатием вне формы не
  прерывает отображение незавершённой записи.
- Системная тема обновляется при изменении темы устройства.
- Убрано жёсткое имя b002 из workflow сборки.
- Добавлены воспроизводимые JS/браузерные регрессии и отдельный workflow UI.
- Выполнены визуальный осмотр входа, dashboard и тёмного «О программе»,
  проверки и настоящий запуск Gradle; подготовлен этот отчёт.

## Метаданные и контракт обновлений

Сохранена идентификация начатой сборки: `2026.09.24-b003-dev`, versionCode `3`,
buildNumber `b003`, buildDate `2026-09-24`, channel `development`.
Дата отчёта не подменяет дату идентификации сборки.

`updateManifestUrl` сейчас пуст: приложение честно показывает, что официальный
источник ещё не подключён. «Установлена последняя версия» показывается только
при корректном ответе источника для того же приложения и канала.

Пример будущего манифеста (иллюстрация, не существующий релиз):

```json
{
  "schemaVersion": 1,
  "applicationId": "ru.portal.app",
  "channel": "development",
  "versionCode": 4,
  "versionName": "example-next-dev",
  "buildNumber": "example-next",
  "publishedAt": "2026-10-01",
  "changelog": "Описание будущих изменений"
}
```

Java принимает только HTTPS без userinfo, не следует редиректам, ограничивает
ответ 64 KiB и время ожидания. Токены входа и компания сервису обновлений не
отправляются. UI проверяет схему, типы, канал, applicationId, дату и размеры
полей; отображаемый текст экранируется. Ссылка на APK не используется.

окружении/транспорте не установлена окончательно; это не считается успешной
интеграционной проверкой. Код сервера ради обхода сброса не изменялся.

Android SDK отсутствует по стандартному локальному пути; `ANDROID_HOME` и
`sdk.dir` не заданы. Компиляция Java, упаковка и запуск на Android не состоялись.
Нельзя считать браузер с имитацией Java bridge полноценной проверкой Android
WebView или настоящего HTTPS-запроса обновлений.

CI workflow подготовлены, но на GitHub в этой задаче не запускались: push нет.

## Ограничения и предлагаемый Этап 3

1. Подготовить Android SDK, получить debug APK и проверить на телефоне:
   WebView/Java bridge, клавиатуру, системный Back, размеры текста, сетевые
   ошибки, реальную многокомпанейность и технический аудит.
2. Повторить HTTP-тесты в рабочем сетевом окружении/CI; прогнать миграцию
   на резервной копии настоящей базы b005 и проверить совместимость BOT.
3. Подключить официальный HTTPS-источник обновлений и подписанное
   распространение APK; установку проектировать отдельно.
4. Заменить временный V/ART окончательным цифровым оригиналом.
5. Продолжить onboarding сторонних компаний и сотрудников, затем документы
   и новости. Сейчас будущие модули скрыты, фиктивных рабочих экранов нет.

Глобальные настройки стоимости/лимитов компаний остаются в API Этапа 1;
этот этап добавляет выбор компании и поддержку, а не полный биллинг UI.
Аудит в UI показывает ограниченную первую страницу, не заменяя системный
инструмент просмотра всего журнала.
