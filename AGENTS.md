# AGENTS.md — обязательный протокол PORTAL

Для любого агента, работающего с этим репозиторием (ChatGPT, Codex, GBI и другие):

1. До начала любой задачи открой и прочитай `PORTAL_MASTER_ROADMAP.md`.
2. Считай его единственным каноническим реестром требований, статусов и незавершённой работы.
3. Не начинай реализацию задачи, которой нет в разделе «Входящие / Принять в работу» или которая не была туда добавлена.
4. Перед изменениями переведи задачу в «В работе» и укажи дату/ветку.
5. После реализации обязательно обнови тот же `PORTAL_MASTER_ROADMAP.md`: результат, тесты, commit/SHA, остаток работы и следующий шаг.
6. Не храни уникальные изменения только локально. До завершения работы изменения должны быть committed и pushed в канонический GitHub-репозиторий.
7. Не выпускай релиз из боковой ветки. Release candidate обязан происходить из текущей канонической release/recovery-линии, указанной в master-файле.
8. Не удаляй утверждённые функции, тарифы, права, документы или данные ради рефакторинга без отдельного решения владельца.
9. VPS разворачивается только из зафиксированного Git commit/tag. Телефон и рабочий ПК — клиенты/рабочие терминалы, не мастер-хранилища.
10. Если фактический код расходится с master-файлом — останови релиз, зафиксируй расхождение в master-файле и сначала выполни reconciliation.
11. VPS source mirror `/srv/portal-source/repo` является только серверной копией GitHub, не отдельной веткой истины. Перед серверной работой синхронизируй его через `ops/sync_vps_source_mirror.sh` с веткой/commit, указанными в master-файле; скрипт обязан отказать при локальных изменениях.

Любые другие отчёты и документы считаются справочными. Если они противоречат `PORTAL_MASTER_ROADMAP.md`, приоритет имеет `PORTAL_MASTER_ROADMAP.md`.
